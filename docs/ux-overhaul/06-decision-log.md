# 06. Decision log

Kept as the work goes, newest at the bottom. One line each: what was decided, why, what it cost. Dates are 2026. AI-assisted.

| When | Decision | Why | Cost |
|---|---|---|---|
| 11 Sep, Phase 0 | Audit on a fresh production build on port 3210 with the log mailer and the Docker database; never the dev server, never production | The dev server rewrites `.next` while a build runs and corrupted the route types once already; production data is never touched by local work | One extra build per audit pass |
| 11 Sep, Phase 0 | One theme in the audit set (the app is dark only by the 5 Sep decision); three widths, 390, 768, 1440 | A light theme does not exist; adding one is new scope | Nothing |
| 11 Sep, Phase 0 | Screenshots come from one script, `scripts/ux-audit/shoot.ts`, that walks every state by moving the seed project through its phases and putting it back | The after set must be the same frames as the before set, taken the same way, or the comparison lies | The script is 200 lines the product does not need; it lives under `scripts/ux-audit/` |
| 11 Sep, Phase 0 | Lighthouse runs from the npx cache (`lighthouse@12.8.2`), not as a dependency | A one-off measuring tool does not belong in `package.json` | The first run downloads it |
| 11 Sep, Phase 0 | The audit server logs to a file, not to the harness pipe | A background task's stderr pipe was closed under it, every log write threw EPIPE, Next logged the throw, and the process spun at 99 percent CPU. Not the app's fault, but it cost forty minutes | Nothing |
| 11 Sep, Phase 0 | Friction numbers F-01 to F-37 are frozen once written | Later documents cite them | Nothing |
| 11 Sep, Phase 0 | Per-page Lighthouse JSON is read and discarded; only `summary.json` is kept | 6 MB of reports for twelve numbers | The raw audits can be re-run with one command |
| 11 Sep, Phase 1 | Contrast is fixed by changing `--faint`, not by adding a colour | Every failure was the one token; ember text already passes | Decorative borders on `--faint` get slightly lighter |
| 11 Sep, Phase 2 | The toast reads a non-httpOnly cookie and clears it itself | A render cannot clear a cookie in the App Router, and a URL flag repeats on reload and back | The cookie can only ever hold a sentence like "Marked paid"; never a secret, by contract in `src/lib/flash.ts` |
| 11 Sep, Phase 2 | `StickyAction` scrolls to the real control and never submits | Agreeing and signing off stay deliberate taps; a bar that agreed for you would be the wrong kind of convenient | Two taps instead of one on a long page |
| 11 Sep, Phase 2 | The review's sticky bar targets both choices, not the sign-off | A bar that carried only "Sign off" would lean on the client | Label is "Say how it went" |
| 11 Sep, Phase 2 | The day-30 notice is written lazily by the client home, not by a scheduler | There is no scheduler and the architecture forbids adding one for this | A client who never opens the page after the unlock never gets the email; the team's attention list already covers that silence |
| 11 Sep, Phase 2 | Cancel, rotate link, forget referral, delete image and close go through one `Confirm` dialog | One pattern for the five irreversible things | A refusal after the dialog closes arrives as a toast |
| 11 Sep, Phase 2 | Admin tables become cards under 900 px through one `DataList` | The team reads the dashboard on a phone on the way to a call | Column labels repeat on every card |
| 11 Sep, Phase 2 | The admin project page is folds that open by phase, plus a "waiting on" line under the title | Eleven always-open cards hid the one that mattered | A fold the phase does not open is one tap away |
| 11 Sep, Phase 2 | The locked questionnaire shows answered questions only, with "N not answered" per section | Nineteen placeholders that nothing could act on | A reader who wants the empty questions sees them when the questionnaire is open for changes |
| 11 Sep, Phase 2 | No `loading.tsx` in either zone; a top progress line (`NavProgress`) instead of a skeleton | A `loading.tsx` streams the page, and a `notFound()` after the shell has gone out answers 200: `/day30`, `/thanks` and a bad token stopped being real 404s, which criteria 10 and 24 and four e2e tests require | The pause shows as a line, not a page shape |
| 11 Sep, Phase 2 | The sticky bar's button is named "[label], further down the page" | Two buttons with the same accessible name broke every anchored locator and would confuse a screen reader | None |
| 12 Sep, after the merge | Ending a project moves to the top right of the title row, and Close joins Cancel there | Ayush asked twice where the cancel control was. Quiet was right, the foot of a 4,000 px phone page was not, and Close was inside the Day 30 fold, so the same idea had two homes | The one irreversible action is now one scroll-free tap away; the confirm dialog is what stops a mis-tap |
| 12 Sep | That control becomes an outlined button rather than a muted text link | A third ask. Moving it was not enough: 12 px grey mono beside a bold title does not read as a control on a dark page | It has more presence than a destructive action usually earns, which the confirm dialog offsets |
| 12 Sep | The client's one task card is labelled "Pending task", not "What we need from you" | Ayush's own word for it since the first redesign brief, and the shorter label leaves the heading to carry the meaning | Singular on purpose: the phases are sequential, so a client never has two |
| 12 Sep | The client's redirecting actions flash a toast; the ones that stay on the page do not | Ayush asked for a confirmation on every client action. Four ended in a silent redirect; the rest already confirm inline, and an inline card that persists beats a toast that vanishes | One line of copy per action, no new component |
